# ADR-0004：值支持 `${VAR}` 引用插值

状态：accepted（2026-08）

## 背景

同 key 覆盖是整体替换。PATH 追加是高频需求（项目工具目录前置），不支持引用时用户在 `.env` 里写 `PATH=D:\tools` 会丢掉整个系统 PATH——静态文件拿不到运行时环境，手工拼不现实。

## 备选

| 方案 | 结论 |
|------|------|
| 不支持 | ❌ PATH 场景无解，覆盖系统变量成为裸风险 |
| 只给 PATH 特殊语法（如 `PATH+=`） | ❌ 自造非标准语法，且其它变量（JAVA_TOOL_OPTIONS 拼接等）同样有引用需求 |
| 通用 `${VAR}` 插值（dotenv-expand 风格） | ✅ dotenv 生态事实标准，语法可直接迁移认知 |

## 决策

- 只支持 `${VAR}` 形式（边界明确，不解析 `$VAR` 简写）；不做转义
- 展开发生在**合并前**：lookup = 父环境（即将被覆盖的完整子进程 env，含系统变量 + DSH 注入）+ 同文件更早定义且已展开的变量（文件顺序敏感）
- 未定义引用展开为空串（保留 `${VAR}` 字面量更易造成隐蔽污染）

## 后果

- `PATH=D:\tools;${PATH}` 前置追加可用，覆盖系统变量不再有裸风险
- 通用：任意变量的值都可引用，不止 PATH
- 代价：字面量 `${...}` 写不进 `.env`（可接受，无此需求）；行序影响可见性（dotenv-expand 同语义）
- 独立函数 `expandDotEnv(env, parent)`，可单测（test-spawnspec.mjs Test 7-11）
